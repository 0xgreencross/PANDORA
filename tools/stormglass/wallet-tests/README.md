# STORMGLASS wallet tests

Run from the repo root (Node with `playwright` and `ethers` 6.13.2 on `NODE_PATH`, Chromium at `/opt/pw-browsers/chromium` or `$CHROMIUM`):

    NODE_PATH=/home/claude/node_modules node tools/stormglass/wallet-tests/ritual.js index.html      # node --check, id audit, vm smoke test
    PORT=8932 bash tools/stormglass/wallet-tests/run.sh                                                # all wallet cases against index.html
    PORT=8932 TARGET=/path/other_index.html LABEL=main CASES=a1,b bash tools/stormglass/wallet-tests/run.sh
    PORT=8932 SCRIPT=shots.js bash tools/stormglass/wallet-tests/run.sh                                # picker + connected dialog at the six law-8 sizes
    PORT=8932 SCRIPT=witness-shots.js PREFIX=index bash tools/stormglass/wallet-tests/run.sh          # open sale with the WITNESS button at the six law-8 sizes + 320x640 (SHOTS=dir, QUERY=?practice=1 CLOSED=1 for the practice page)

    PORT=8932 RELEASE=1 LABEL=release bash tools/stormglass/wallet-tests/run.sh                         # release verification: every case of manifest.json, nothing else
    NODE_PATH=/home/claude/node_modules PORT=8941 OUT=dir node tools/stormglass/wallet-tests/selftest.js  # the harness self-tests (about 6 minutes)

The full run takes about ten minutes: start it in the background (`(setsid nohup timeout 1800 bash run.sh > log 2>&1 &)`) and poll the log. A log without a final `XDONE rc=N` line means run.sh itself was killed: a failure.

## Release runs and the manifest (audit 5)
`manifest.json` lists every case module (`wallet.test.js`, `audit2.test.js`, `audit3.test.js`, `audit3b.test.js`, `harness.test.js`, every `audit4*.test.js` and `audit5*.test.js`) with its group and the exact ids it must register. With `RELEASE=1` the runner refuses to start (exit 2, results status `manifest-mismatch`) when a listed module is missing, a module or an id is present but not listed, a listed id is not registered, or a group differs; `RELEASE=1` also refuses `CASES` and any preloaded code in `NODE_OPTIONS` (`--require`, `--import`, `--loader`). A missing audit module therefore can never shrink a release run. Adding a module or a case is deliberate: add it to manifest.json in the same commit (`node wallet.test.js --print-manifest` prints the current registration to copy from). Runs without `RELEASE=1` are labelled `subset` (CASES given) or `all (not release-verified)` and print a `WARN` line when the registration differs from the manifest.

## Results file (schema `stormglass-wallet-results/2`, audit 5)
`$OUT/results-$LABEL.json` is one object (it used to be a bare array of case rows: that array is now the `cases` field, same row format plus `file`, the module that registered the case). Readers of the old format: use `j.cases` (or `Array.isArray(j)?j:j.cases`). Fields: `runId` (unique), `label`, `mode` (`release` / `subset` / `all (not release-verified)`), `status` (`starting`, `running`, `passed`, `failed`, `incomplete`, `interrupted`, `harness-failure`, `selection-error`, `registration-error`, `manifest-mismatch`), `completed` (every selected case executed and the run was not cut short), `exit` (the exit status, or `"interrupted"`; `exitCode` always has the number), `startedAt`, `finishedAt`, `interruptedBy`, `running` (the case in progress when it was cut short), `target` (path, bytes, sha256, `source`: `commit` = `git rev-parse HEAD` of the repo holding TARGET, `path` in that repo, `matchesHead` = TARGET's bytes equal the file in that commit, or `commit:"unknown"` and a `reason`), `harness` (commit, tree hash of this folder, uncommitted files, and the sha256 of every file of this folder Node loaded), `deps` (node, playwright and ethers as actually loaded, the ethers UMD sha256, chromium version), `env` (CASES, RELEASE, timeouts, NODE_OPTIONS, OUT, PORT), `manifest` (the comparison with manifest.json), `registered`, `groups`, `selected`, `executed`, `passed`, `failed`, `timedOut`, `unexecuted`, `harnessFailures`, `persistence` (`ok`, `snapshots`, `failures`, `previous`).

Persistence: the file is written atomically (a temp file in the same folder, fsync, rename) before the first case, after every case and at the end. Any failure to write it is a harness failure that makes the exit status nonzero for the rest of the run (a later good write records it, never clears it); if the results cannot be written at the start, no case runs. A file of the same name left by an earlier run is first renamed to `results-$LABEL.prev-<its runId>.json` (`prev-legacy-<mtime>` for the old array format), so an older successful run can never pass for the current one; if the final write fails, the file on disk is the previous snapshot, which says `running`, never `passed`. A dependency, the target or a case module that cannot be loaded still ends with a results file (`harness-failure` / `registration-error`).

Watchdogs: `CASE_TIMEOUT_MS` (default 120000) fails a case that gives no result in time (`timedOut`), closes its contexts and refuses any late `boot()` from it; if the browser then does not answer within 15 s it is killed and the run ends `incomplete`. `RUN_TIMEOUT_MS` (default 2700000) ends the whole run as `interrupted`. SIGTERM / SIGINT (run.sh passes them to node) write an `interrupted` result and exit 143 / 130.


- `mockwallet.js`: mock EIP-1193 wallets (EIP-6963 announcements, `window.ethereum`, `providers[]`), every request logged; chain, accounts, delays, rejections, sync throws, malformed answers, never-answering calls, gates the test opens, and events.
- `fakechain.js`: answers the public RPCs the page reads (`eth_call` for the STORMGLASS / GLASS / SMALL WEATHER ABIs, blocks, receipts). Every other outside request is refused; ethers is served from the local copy of the cdnjs file.
- `wallet.test.js`: cases a-m (wrong chain, races, picker, remembered choice, events, revoke, amount boxes, phone path) and w1, w3 (the WITNESS call-to-action under COLLECT: visible, big enough, opens the sheet, sends once; absent when nothing is on sale). n1-n6 (typed amounts: `0,001` from a comma-locale keypad sends exactly 0.001 ETH in the witness, pledge and bid boxes; ambiguous or bad amounts send nothing and toast "Type an amount like 0.01"; a table of `parseAmount`). Results go to `$OUT/results-$LABEL.json` (default `/tmp/claude-0/pr1test`).

- `audit2.test.js` (loaded by `wallet.test.js`): the audit-2 regression cases. q1-q6 one write at a time (q1: the wallet holds the first request at a gate while four more presses are turned away, then a deliberate second payment; fast presses, presses while a connection or a wallet confirmation is pending, refusal, an unknown outcome after the hand-off); r1-r9 following a submitted transaction on the mainnet HTTP readers (silent wallet, a failing or hanging first reader, reverted, sped up, cancelled, replaced, dropped); k3-k6 revocation and reconnect (> 5 s, unsupported, never answered, two wallets); m4-m5 a deterministic WalletConnect provider mock (pair, a transaction, DISCONNECT ends the session, the phone ends it); h6-h9 wallet identity (shared rdns, dead first provider, legacy name collisions, ambiguous saved choice); p1-p5 the COLLECT dialog against stale callbacks (close/reopen, another option, account change, a new day while connecting or confirming); v1-v3 the last look before `eth_sendTransaction`; c1-c2 IME composition across redraws and day changes.

The results JSON is rewritten after every case, and a run that stops early (browser crash, a promise that never settles) still prints RAN, NOT RUN and the summary and leaves the partial results (audit 4, G1). Chromium runs with `--webrtc-ip-handling-policy=disable_non_proxied_udp`: WebRTC gathers no UDP candidate and sends no STUN packet (a4h1).

Exit status: 0 only when every selected case ran and passed (`pass` must be exactly `true`) and every results snapshot was saved; 1 when a results write fails, when a case fails (its assertion, an exception, an uncaught page error or unhandled rejection or renderer crash in any context the case opened), when the browser dies (the cases not run are listed), when the run stops without finishing, when the browser cannot launch, or when run.sh's HTTP server does not start; 2 for an unknown id in `CASES`, a selection of zero cases, or a duplicate or malformed case id at registration, a case module that does not load, or (RELEASE=1) a registration that differs from manifest.json; 130 / 143 when interrupted by SIGINT / SIGTERM. `run.sh` passes Node's status through. Every exit path writes the results file (see above). `selftest.js` proves each of these on a temporary copy of this folder (temporary cases, `selftest-fault.js` preloaded to make results writes, renames and opens fail). Groups: `CASES=@orig` (38), `@audit2`, `@audit3` (audit3.test.js when present), `@audit3b` (audit3b.test.js when present), `@harness`, `@audit4` (every audit4*.test.js), `@audit5` (every audit5*.test.js); a group is taken from the file that registered the case.

The log prints the selected ids (with the target's sha256) and the ids that ran; `results-$LABEL.json` has per case `ms`, `contexts`, `wallet` ([{asked: eth_sendTransaction requests, sent: what the mock let through}] per context), `outsideRefused`, `socketsRefused`.
