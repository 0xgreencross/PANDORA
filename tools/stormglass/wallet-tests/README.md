# STORMGLASS wallet tests

Run from the repo root (Node with `playwright` and `ethers` 6.13.2 on `NODE_PATH`, Chromium at `/opt/pw-browsers/chromium` or `$CHROMIUM`):

    NODE_PATH=/home/claude/node_modules node tools/stormglass/wallet-tests/ritual.js index.html      # node --check, id audit, vm smoke test
    PORT=8932 bash tools/stormglass/wallet-tests/run.sh                                                # all wallet cases against index.html
    PORT=8932 TARGET=/path/other_index.html LABEL=main CASES=a1,b bash tools/stormglass/wallet-tests/run.sh
    PORT=8932 SCRIPT=shots.js bash tools/stormglass/wallet-tests/run.sh                                # picker + connected dialog at the six law-8 sizes
    PORT=8932 SCRIPT=witness-shots.js PREFIX=index bash tools/stormglass/wallet-tests/run.sh          # open sale with the WITNESS button at the six law-8 sizes + 320x640 (SHOTS=dir, QUERY=?practice=1 CLOSED=1 for the practice page)

The full run takes about four minutes: start it in the background (`(setsid nohup timeout 900 bash run.sh > log 2>&1 &)`) and poll the log.

- `mockwallet.js`: mock EIP-1193 wallets (EIP-6963 announcements, `window.ethereum`, `providers[]`), every request logged; chain, accounts, delays, rejections, sync throws, malformed answers, never-answering calls, gates the test opens, and events.
- `fakechain.js`: answers the public RPCs the page reads (`eth_call` for the STORMGLASS / GLASS / SMALL WEATHER ABIs, blocks, receipts). Every other outside request is refused; ethers is served from the local copy of the cdnjs file.
- `wallet.test.js`: cases a-m (wrong chain, races, picker, remembered choice, events, revoke, amount boxes, phone path) and w1, w3 (the WITNESS call-to-action under COLLECT: visible, big enough, opens the sheet, sends once; absent when nothing is on sale). n1-n6 (typed amounts: `0,001` from a comma-locale keypad sends exactly 0.001 ETH in the witness, pledge and bid boxes; ambiguous or bad amounts send nothing and toast "Type an amount like 0.01"; a table of `parseAmount`). Results go to `$OUT/results-$LABEL.json` (default `/tmp/claude-0/pr1test`).

- `audit2.test.js` (loaded by `wallet.test.js`): the audit-2 regression cases. q1-q6 one write at a time (fast presses, presses while a connection or a wallet confirmation is pending, refusal, an unknown outcome after the hand-off); r1-r9 following a submitted transaction on the mainnet HTTP readers (silent wallet, a failing or hanging first reader, reverted, sped up, cancelled, replaced, dropped); k3-k6 revocation and reconnect (> 5 s, unsupported, never answered, two wallets); m4-m5 a deterministic WalletConnect provider mock (pair, a transaction, DISCONNECT ends the session, the phone ends it); h6-h9 wallet identity (shared rdns, dead first provider, legacy name collisions, ambiguous saved choice); p1-p5 the COLLECT dialog against stale callbacks (close/reopen, another option, account change, a new day while connecting or confirming); v1-v3 the last look before `eth_sendTransaction`; c1-c2 IME composition across redraws and day changes.

The results JSON is rewritten after every case, and a run that stops early (browser crash, a promise that never settles) still prints RAN, NOT RUN and the summary and leaves the partial results (audit 4, G1). Chromium runs with `--webrtc-ip-handling-policy=disable_non_proxied_udp`: WebRTC gathers no UDP candidate and sends no STUN packet (a4h1).

Exit status: 0 only when every selected case ran and passed (`pass` must be exactly `true`); 1 when a case fails (its assertion, an exception, an uncaught page error or unhandled rejection or renderer crash in any context the case opened), when the browser dies (the cases not run are listed), when the run stops without finishing, when the browser cannot launch, or when run.sh's HTTP server does not start; 2 for an unknown id in `CASES`, a selection of zero cases, or a duplicate or malformed case id at registration. `run.sh` passes Node's status through. Groups: `CASES=@orig` (38), `@audit2`, `@audit3` (audit3.test.js when present), `@audit3b` (audit3b.test.js when present), `@harness`.

- `audit3.test.js` (@audit3): x1-x7 late explanations in the COLLECT dialog, y1-y10 the replacement scan, z1-z4 the wrong-chain stop and SWITCH.
- `audit3b.test.js` (@audit3b): the coverage-matrix cases u1-u17 (an abandoned connection replaced by a new CONNECT, the 8 s WalletConnect fallback text, the busy message before/after the hand-off, the last-look microtask gap; guards for wallet metadata as text, tampered stored WalletConnect links, false/4902 switches, remembered wallet by key, no fallback after a refusal, lock identity, WalletConnect event filtering, the WalletConnect load failure sheet, sync-throwing sends, malformed account lists, late announcements, no wallet). The mock's `announceAfter` (a late wallet) is used by u15.
- `audit4*.test.js` (@audit4; audit4.test.js): a4c1-a4c7 a chain change between the last look and the hand-off (microtask sweeps, gas estimation, the last look's own requests; guards: an earlier wallet's events, the payment's own switch announced late, a change after the hand-off), a4w1-a4w10 WalletConnect `session_request_sent` correlation (other sessions/providers/requests, duplicates, malformed events, switches, no session topic: the OPEN link only carries requestId + sessionTopic for this request), a4r1-a4r12 receipt validation (status, transactionHash, blockNumber vs the send block, blockHash, from/to, replacements, reader fallback, deadlines, the one-receipt policy, WITNESS and COLLECT end to end). The fake chain's default receipt is mined in the head block (audit 4). audit4scan.test.js: a4s1 (every write entry point sends what was pressed) and a4s2-a4s7 (seats after an account change, a dead wallet as the last-resort reader, an account change without an event, a WalletConnect link after the 20 s sheet, a stale remembered WalletConnect app, COLLECT after DISCONNECT). audit4review.test.js: a4h1 (no WebRTC/UDP leaves a case) and a4v1-a4v7 (the second audit: guards for the S repairs, a wallet reader that never answers a read, async observers).
- `harness.test.js` (@harness): hz1 shows nothing real is reachable (an RPC write is answered by the fake chain; relay.walletconnect.org over https and wss, and any other host, are refused and recorded; no wallet unless the test makes one; no browser extension); hz2 shows a closed context sends nothing more and the next one starts empty.
- Each case gets a fresh browser context (own storage, service workers blocked, every WebSocket refused); the runner closes every context the case opened. The log prints the selected ids (with the target's sha256) and the ids that ran; `results-$LABEL.json` has per case `ms`, `contexts`, `wallet` ([{asked: eth_sendTransaction requests, sent: what the mock let through}] per context), `outsideRefused`, `socketsRefused`.

No real wallet, no real RPC, no real transaction is involved.
