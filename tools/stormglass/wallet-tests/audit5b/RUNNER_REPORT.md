## 2. Design
- **`tools/stormglass/wallet-tests/runner.js` is the only implementation** (no second copy). `begin(module,{suite,label,caseMs})` is each entry's first call: only when that file is the main script, it creates the run identity, installs SIGINT/SIGTERM (interrupted result, 130/143), unhandledRejection (fails the running case and the run), uncaughtException, beforeExit (event loop drained), an `exit` safety net (any other `process.exit` is recorded as status `aborted`, never a success) and the whole-run watchdog, then **moves the earlier results file to `.prev-<runId>` and writes the first "starting" snapshot before any dependency, page or case module is loaded** (if that fails nothing runs, exit 1). For any other loader (shots scripts, case modules) it does nothing. `run(spec)` does registration/manifest checks, selection, launch, the cases, snapshots and the exit status, unchanged from the audit-5 production runner plus the additions below.
- wallet.test.js: its RUN section is now a spec (cases, module loading, `manifest.json`, TARGET); exports `bumpEpoch` and `earlyError`. staging.test.js: header gets the `begin` line, its `T` collects malformed/duplicate ids under the runner (exit 2 **with** a results file) instead of exiting before any file exists, the unused `require('playwright')` is gone, and the RUN section below `module.exports={CASES,T}` is a spec with **its own committed manifest `tools/stormglass/staging/manifest.json`** (same schema-1 format as manifest.json: one module `staging.test.js`, group `@staging`, 32 ids). The case section is untouched.
- Additions to the shared machinery: **cleanup deadline** (10 s per context, `CLEANUP_TIMEOUT_MS` default 30000 per case, 10 s for the final browser close; a context that does not close fails the case and is a harness failure; previously production only recorded `contextsDidNotClose`); **manifest self-validation** (malformed or duplicate ids in the manifest itself → RELEASE refuses, `malformedIds`, `duplicateIds`); `cleanupTimedOut` list; `suite` field; a target served from disk (the staging page) is re-hashed at the end (`target.sha256AtEnd`, a change is a harness failure). Staging default `CASE_TIMEOUT_MS` 480000 (st25 takes ~119 s quiet, >240 s under load); production stays 120000.
- Staging results add `staging.{page, stamp, candidate:{rev, commit, sha256 (stamp), gitSha256 (= sha256 of git show <commit>:index.html), matchesStamp}, index:{sha256, matchesStamp, source}}`; `target` is the staging page with full sha256 and `source.commit/matchesHead`; `harness` has commit, a tree per folder (staging, wallet-tests), dirty files and the sha256 of every loaded file of both folders; `deps` node/playwright/ethers/ethers UMD sha256/chromium.
- Merge notes: manifest.json format unchanged (the page agent adds its `audit5b*.test.js` entry, group `@audit5`, loaded by the existing `audit5*` rule); the staging agent appends st33+ to the `ids` array of staging/manifest.json (or regenerates it with `node tools/stormglass/staging/staging.test.js --print-manifest`) and adds cases above `module.exports` as before. Behaviour changes for staging: results are the schema-2 object (`j.cases` holds the old rows), an old array file is moved to `.prev-legacy-<mtime>`, Chromium also gets `--webrtc-ip-handling-policy=disable_non_proxied_udp` like production.
