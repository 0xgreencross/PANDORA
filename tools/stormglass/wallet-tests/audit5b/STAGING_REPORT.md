## 1. The boundary as found (stage.js at 50ac8a5)
- **SIMULATION**: no real provider. `SG.eth()` (461) returns the simulated window.ethereum or nothing; `SG.detail()` (462) drops every non-simulated announcement; `SG.wcNS()` (464) always returns the simulated namespace, so /wc.js never loads and no relay socket opens; every cross-origin JSON-RPC POST is answered by the simulated chain (fetch wrap 223-240).
- **REAL WALLET**: every provider reaches the page through the three build taps (build.js 53-60: window.ethereum ×11 → `__SG.eth()`, the one EIP-6963 listener → `__SG.detail()`, `_wcGlobal` → `__SG.wcNS()`), each returning a memoised wrapper (`wrap`, 426-447); providers[] wrapped on read (435); remembered choices (`stormglass.wallet`, `SG_WC_APP`) are keys, never providers. Real contact, for connection/session operations:
  - no prompt: `eth_chainId`, `eth_accounts`;
  - after the gate (`gate`, 284-290): `eth_requestAccounts`, `wallet_switchEthereumChain`;
  - `wallet_revokePermissions` (DISCONNECT); read-only calls (eth_call, eth_blockNumber, eth_getBlockByNumber, eth_getLogs, receipts/tx by hash for non-simulated hashes): forwarded, reach the wallet's node only on the page's wallet-read fallback (after three HTTP readers fail, which the simulated readers do not);
  - **WalletConnect: the real `EthereumProvider.init` (wrapNS, 456) opens the relay connection on CONNECT, before the gate, and restores a stored session (REAL shares the live site's localStorage); pairing = `raw.enable()` (438) after the gate; `disconnect` (439); session events.** WalletConnect's own hosts pass the fetch wrap in REAL mode (`WC_HOST`, 224/233), JSON-RPC writes refused first (`HTTP_WRITE`, 231).
- **Intercepted / refused at the wrapper** (`guard`, 414-425): eth_sendTransaction → intercept panel + simulated result (421-423); TX + SIGN lists (policy.js 26-27: wallet_sendTransaction, wallet_sendCalls, eth_sendRawTransaction, eth_signTransaction, eth_sendUserOperation, wallet_grantPermissions, eth_sign, personal_sign, eth_signTypedData*) → shown and refused 4001 (424); everything else → 4200 (425). The method is read once (414). Belt inside the WalletConnect bundle (450-453).
- Chain outcomes stay simulated. The automated harness blocks every socket and outside host: a property of the test environment, not evidence that the deployed page cannot reach a relay. Written up in STAGING5_REPORT.md new section 4b (+ corrected "Network contact" row and limitations).

## 5. Limitations
- Real relay delivery, real wallets and real pairing are not exercised; st33/st37 use the harness's mock WalletConnect and prove only the wrapper and gate order. EthereumProvider.init (relay socket, stored-session restore) still precedes the gate by design of the page flow; no wallet request goes out before it. Gating init itself would hang st9/st21 (they call init directly) and was not done.
- The wallet-read fallback would read the real chain through the wallet (reads only); not reachable with the simulated readers, documented.
- The owed controls change simulated owed[] only; the contract's rule is modelled.
